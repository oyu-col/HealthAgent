# .gitignore：源码与运行生成物的分界

- 对应源码：`.gitignore`
- 核对日期：2026-10-11
- 目录导航：[本目录说明](README.md)
- 源码：[.gitignore](../.gitignore)

本文件为未来/现有 Git 使用规定排除范围。当前工程所在目录没有可用 Git 元数据，但忽略规则仍表达应当如何管理源码与私密运行数据。

| 类别 | 主要规则及意图 |
| --- | --- |
| 凭据 | .env、.env.*，例外保留 .env.example |
| Python | .venv、__pycache__、pytest/Ruff 缓存、.pytest-tmp 与 .pytest-tmp-* 测试数据、临时 smoke、egg-info、build、coverage |
| 前端 | node_modules、.next、dist、test-results、playwright-report、pnpm store |
| 私有数据 | data、SQLite/db 文件及 WAL/SHM 辅助文件 |
| 评测输出 | .benchmark-* 临时评测数据目录、benchmark/runs 原始运行目录，避免运行结果与固定用例混在源码中 |
| 日志 | *.log，避免无意提交运行信息 |

它不会删除文件、阻止程序读取文件、替代备份或加密，也不会让已被 Git 跟踪的秘密自动退出版本历史。文档镜像以这类边界为依据排除依赖、缓存、构建和私有数据库，但仍记录公开配置模板、依赖锁和手写测试。

`.pytest-tmp-*/` 允许并发测试显式选择不同的临时目录，避免共享默认目录时发生清理竞争和 Windows SQLite 文件锁。`.benchmark-*/` 对应 runner 创建的临时真实数据库环境；`benchmark/runs/` 则保存逐次执行报告、诊断及基线快照等生成物。忽略它们不意味着这些内容一定安全，也不意味着可以不经检查直接公开。

Phase 11/12 的固定案例、schema、grader、runner 和回归测试是可维护源码，不在上述运行目录规则之内。若需要保留可审阅的脱敏评测结果，应有意选择受维护的交付位置并核查内容；不能把全部运行目录直接放行。

修改时应检查是否误排除应提交的配置/测试，也要防止放行健康数据。忽略规则只控制 Git 的默认发现行为，不会执行清理，不会阻止临时文件生成，也不改变当前工作区没有 Git 元数据这一事实。
